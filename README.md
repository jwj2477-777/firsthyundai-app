# 퍼스트현대 무료 자동 수집 안드로이드 앱 v1.6.1

> **중요:** 현재 제공 파일은 Android APK *빌드 가능 소스*입니다. 실거래 API 키·GitHub 저장소 연결·자동 실행은 각자 계정에서 설정해야 합니다. 이 작업 환경에서는 실제 APK 컴파일과 실휴대폰 설치 검증을 아직 수행하지 못했습니다. 데이터 파일에는 허위 샘플 거래/뉴스를 넣지 않았습니다.

## v1.6.1 — 13개 단지 상세 기본정보 완성 (학군 제외)

2026-10-19 외부 공개 자료 대조 기준으로, 관심 **13개 개별 단지 모두** 세대수·동수·사용승인일·층수·지역난방 여부·주차대수·전기차 충전기 대수·건폐율·용적률·시공사·주소·관리사무소 전화번호를 등록했습니다. 최초 F13 자료는 사용자가 제공한 네이버페이 부동산의 수치를 유지했습니다.

- 단지 기준 출처: `source_url`에 있는 KB부동산 단지정보 또는 센터니얼 당근부동산.
- 전기차 충전기 대수: 국토교통부 공동주택 단지 기본정보 **2026-09-09 K-apt 공개 추출본**, `detail_source_url` 단지별 링크 및 `kapt_code` 병행 기록. EV 충전 수치는 물리적으로 변경될 수 있습니다.
- 관리사무소 전화번호: KB부동산 공개 연락처, K-apt 공개 관리 주체 연락처, K-apt 입찰 공고 등에서 교차 확인.
- **차이 발견**: 퍼스트파크 F14 주차 KB 1,229대/K-apt 1,224대, 마스터뷰 F21 KB 1,113대/K-apt 1,106대, 마스터뷰 F23-1 KB 780대/K-apt 767대, 아트윈푸르지오 KB 1,463대/K-apt 1,399대. 앱은 KB 수치를 기준 표시하되 대체 수치를 보관하고 **자료 차이·확인사항 보기**로 차이를 표시합니다. 해당 단지는 관리사무소에 최신 총 주차대수를 확인하는 것이 안전합니다.
- **추가 확인 필요**: 마스터뷰 F23-1 난방 KB **지역난방** / K-apt 기반 **중앙난방**으로 불일치하여 기본 화면에는 `확인 전`으로 남깁니다. 센트럴파크3차 층수 KB **38~40층** / K-apt 최고 **39층**으로 차이가 있어 앱에 경고를 넣었습니다.
- F13 사용자가 제공한 **전기차충전 14대**는 우선 유지했습니다. 학교·학군 정보와 저작권이 있는 평면도 파일은 이번에 등록하지 않았습니다.
- 관리자 JSON 내보내기를 실행해도 위 출처·불일치·대체값을 잃지 않도록 필드 보존 테스트를 추가했습니다. 기존 가족/관리자 접근 구분은 유지합니다.

## v1.6 — 중복 없는 단지정보 UI + 상세 기본정보 + 학교 탭

- 단지정보 화면 중복 제거: '확인된 전용면적 유형'과 '실거래 관측 전용면적'의 별도 반복 노출 삭제. **기본정보 / 평형·타입 / 학교·학군 / 실거래 / 평면도·원문** 다섯 개의 큰 탭으로 필요한 내용만 표시.
- 면적별 실거래: 각 전용면적마다 매매·전세·월세 버튼을 네 번씩 반복하지 않고 **거래유형 필터 1개** + **면적별 거래 보기 버튼**으로 통합.
- 사용자 제공 네이버페이 부동산 공개 표기 내용으로 **송도더샵퍼스트파크 13블럭(F13)** 세대수 856, 5개동, 사용승인일 2017-11-17, 36~44층, 지역난방/열병합, 주차 1,233대(세대당 자동 계산 약 1.44대), 전기차충전 14대, 용적률 315%, 건폐율 14%, 관리사무소 032-834-8996, 시공사, 주소 반영. 다른 단지의 신규 상세항목은 독립 검증 전에는 임의로 입력하지 않음.
- 관리사무소 번호 클릭 시 **Android 전화 앱의 번호 입력 화면**으로 연결(자동 통화 없음).
- 새 학교·학군 탭 및 관리자 학교 정보 편집 지원. 학교명과 학교급 및 근거 URL을 함께 등록. **배정학교와 인근 참고학교를 구별**하고, 근거 없는 학교명은 자동 추정하지 않음.
- 관리자 JSON 내보내기가 신규 상세정보와 검증된 학교 목록을 보존하며, 기존의 가족 비공개 임시수정 정책은 유지.
- 기존 실거래 데이터 수집 구조와 관리자 계정 구분, 관심단지 검색 기능 유지.

**추가 학교 샘플 요청:** 해당 단지의 네이버페이 부동산 '학교/학군' 화면 1~2장 또는 텍스트를 제공받으면 항목별 표시를 구체화할 수 있습니다. 화면 내용의 사실 자체를 재확인한 뒤 데이터로 등록하고, 이미지 복제는 하지 않습니다.

## v1.5 — 네이버 원본 연결 + 송도 전체 아파트 자동 검색

**구현된 기능 (2026-10-19)**

- 국토교통부 공개 실거래 자료에 **실제 등장한 송도동 아파트명**을 자동으로 발견하여 기존 13개 관심단지와 함께 목록으로 구성합니다. 원래 자동 수집 파이프라인을 재사용하므로 새로운 유료 API가 필요하지 않습니다.
- 단지별 **거래가 관측된 전용면적**, 매매·전세·월세의 기록 건수, 마지막 계약일을 자동 집계합니다. 면적·거래종류 버튼으로 전체 실거래 화면을 해당 단지/면적/유형에 맞춰 바로 엽니다.
- 전체/관심 13개 단지 구분, 검색, 48개씩 더 보기.
- 네이버페이 부동산 검색 링크를 단지별로 제공합니다. 링크가 직접 등록된 단지는 네이버 **원본 단지 URL**로 연결합니다. 네이버 이미지/데이터베이스를 수집·복제하여 공개 저장소에 저장하지 않습니다.
- 관리자 편집에서 **새로 발견된 단지도** 출처를 확인하여 세대수·난방·타입·평면도 HTTPS URL 등을 편집하고 공개 JSON으로 내보낼 수 있습니다. 미게시 임시 데이터는 관리자 기기에만 남습니다.
- **주의:** 최근 12개월 수집 실거래에 등장하지 않은 단지는 자동 목록에 없을 수 있습니다. 실거래에 등장한 전용면적만으로 전체 평형·평면도 정보를 추측하지 않습니다. 행정상 배정학교나 학군을 추정 표시하지 않습니다.
- 데이터 수집은 기존 국토교통부 실거래가 API를 이용하고, 아파트 기본정보 자동 보강은 공공데이터포털 K-apt 등록 API 인증/단지명 매칭 검증을 거쳐 단계적으로 구현합니다.

**데이터 출처:** [공공데이터포털 전국공동주택표준데이터](https://www.data.go.kr/data/15096285/standard.do), [공동주택 단지 목록제공 서비스](https://www.data.go.kr/data/15057332/openapi.do), [공동주택 기본정보 자료](https://www.data.go.kr/data/15073271/fileData.do). K-apt API와 네이버 사설 API 대량 수집은 이번 버전에서 연동하지 않았습니다.

## v1.4 — 출처 확인 13개 단지 + 관리자 편집·내보내기

2026-10-19 확인 기준, 공개 참고정보 화면에 **13개 개별 단지 세대수**와 링크를 등록했습니다. 공급면적 타입 표시는 원 출처의 **표기상 반올림된 공급면적 ㎡** 기준으로 A/B 등 타입을 구분하고, 앱에서 약식으로 평 환산합니다. 이는 공식 전용면적 합계나 평면도 도면을 의미하지 않습니다.

- 자료 출처: 각 단지 `source_url` 참고(KB부동산 중심, 센터니얼은 당근부동산). 공식 장부·현장 자료와 비교해 고객에게 안내하세요.
- 마스터뷰 23블럭 난방방식은 플랫폼 정보가 상충해 빈칸으로 남겨두었습니다(지역난방/중앙난방 표기 차이).
- 평면도 파일은 저작권·원본 확인 없이 복제하지 않았습니다. 관리자에서 **검증된 HTTPS 평면도 링크**를 입력하면 연결할 수 있습니다.
- 일부 사이트에서 같은 단지의 세대수·동수 표기가 서로 다를 수 있습니다. 현재는 단지별 명시 출처에 있는 세대수를 사용합니다.
- **중요한 v1.3 오류 수정:** 안드로이드 `MainActivity.Bridge.fetch`가 `complexes.json` 조회를 허용하지 않던 누락을 수정했습니다. v1.4 이상으로 다시 설치해야 가족 휴대폰에서 공개 단지정보 파일을 읽을 수 있습니다.

### 관리자에서 데이터 수정하기

1. 관리자 모드 → **단지정보** → 해당 단지 선택 → **선택 단지 수정**.
2. 확인된 세대수·난방·공급면적 타입(117A 등)·전용면적(84.90 등)·평면도 URL, **출처 링크와 검증일**을 입력합니다.
3. **이 기기에 임시 저장**을 누르면 해당 휴대폰의 관리자 모드에서만 바뀐 내용이 보입니다. 가족 모드는 기존 공개 자료만 봅니다.
4. **전체 단지정보 JSON 내보내기** → 저장 위치 선택 → `complexes.json` 저장.
5. GitHub에 본인 계정으로 로그인한 뒤 `data/complexes.json`을 열고 **내보낸 JSON 내용으로 직접 교체해 커밋**합니다. 앱은 GitHub 쓰기 인증 권한을 보유하지 않으므로 자동 게시하지 않습니다.
6. 부모님 앱에서 **단지정보 → 갱신**하면 공개된 새 JSON을 다시 조회합니다.

**보안/데이터 범위:** 이 정보는 공개 GitHub 저장소에 게시되므로 고객·계약 관련 개인정보를 저장하면 안 됩니다. 관리자 임시 저장은 휴대폰 내 WebView 저장소이므로 앱 삭제·휴대폰 초기화 때 사라질 수 있습니다. 병합 후 APK 서명키가 바뀌면 이전 앱의 개인 메모를 백업하고 교체 설치하세요. 관리자 인증 코드는 v1.2와 동일한 독립 인증 방식입니다. `data/complexes.json`을 읽는 공개 기능만 가족에게 제공하며, JSON 파일 저장은 안드로이드 Java 브리지에서도 관리자 모드만 허용합니다.

## v1.3 — 송도 아파트 단지정보 도감 1단계

### 가족이 보는 '단지정보' 탭
- 기존 **주변단지 12개 그룹**을 첫 자료 목록으로 사용합니다. **프라임뷰 20블럭과 25블럭을 분리**해 총 13개 개별 단지정보 항목으로 표시합니다.
- **아파트명 검색**, **세대수**, **난방 방식**, **확인된 전용면적 유형**, **검증된 평면도 링크**, **근거 URL 및 검증일**을 표시할 수 있습니다.
- 실제 거래 기록에서 관측된 전용면적을 별도 표기합니다. 이는 단지의 전체 평형 구성이나 공급면적을 뜻하지 않으며 수집 기간·신고 자료에 따라 누락될 수 있습니다.
- 현재 `data/complexes.json`에 단지 이름과 기존 실거래명 매칭만 넣었으며, **세대수·난방·평형·평면도는 미확인으로 비워 둡니다**. 임의 수치·이미지·출처를 생성하지 않습니다.
- '이 단지 주변단지 실거래 보기'를 누르면 기존 즐겨찾기 실거래로 이동합니다. 프라임뷰는 기존 v1.2의 20·25블럭 통합 실거래 화면으로 이동하므로 상세 단지정보와 구분해서 해석해야 합니다.

### 관리자에서 단지 정보 올리기 (가족과 공유)
1. 원본 `data/complexes.json`의 해당 단지 항목을 GitHub에서 **직접 수정**합니다. 가족용 화면에서는 저장소 편집 링크를 숨깁니다.
2. 세대수는 검증된 정수(`households`), 난방 방식은 문자열(`heating`), **전용면적 기준** 목록은 숫자 배열(`area_types_m2`), 평면도는 `{"label":"84A","url":"https://..."}` 형태의 배열(`floorplans`)로 입력합니다.
3. `source_url`에 자료 출처 HTTPS 주소를 입력하고 `last_verified`에는 실제 검증일(YYYY-MM-DD)을 기록한 뒤 커밋합니다. 확실하지 않으면 `null` 또는 빈 배열을 유지합니다.
4. 가족 휴대폰의 **단지정보 → 갱신**을 누르면 최신 공개 정보를 불러옵니다. 파일 수정 즉시 자동 푸시는 지원하지 않습니다.

**이 구조는 공개 정보만 공유**합니다. 고객명·휴대전화·매물 메모·계약서·내부 비밀번호는 `data/complexes.json`에 기록하면 안 됩니다. GitHub 공개 저장소에 올린 내용은 전 세계 누구나 읽을 수 있습니다. 현재 앱에서 관리자 화면으로 GitHub Secret을 편집하거나 단지정보를 자동 업로드하는 기능은 없습니다.

### 검증 / 배포
- 새 단지정보 화면은 독립 검색과 가족 모드 표시를 위해 추가되었고, 별도 `scripts/test_complexes.js` 단위 테스트를 제공합니다.
- APK 빌드는 GitHub Actions의 **Build Android APK**를 사용합니다. Pull Request에서도 빌드·테스트되도록 workflow를 확장했습니다.
- 소스 변경만으로 부모님 휴대폰에 자동 배포되지 않습니다. 브랜치를 `main`에 병합한 뒤 APK를 새로 빌드하고 업데이트 설치를 해야 합니다.
- 비밀번호·기존 기기별 메모·빌드키 동작은 v1.2를 유지합니다. 교체 설치 시에는 메모를 먼저 별도 백업하세요.

## v1.2 — 관리자 전용 비밀번호 분리

**가족 코드와 관리자 전용 코드는 다른 비밀번호입니다.** 부모님은 기존 가족 코드로 최초 1회 인증 후 자동 로그인하고, 관리자 설정 화면은 별도 관리자 코드로만 열립니다. 부모님은 코드가 있어도 관리자 모드로 바로 들어갈 수 없습니다.

### 관리자 코드 최초 등록 (한 번 필요)

1. GitHub 저장소 `Settings → Secrets and variables → Actions`로 이동합니다.
2. `New repository secret`을 클릭하고 이름에 `FIRSTHYUNDAI_ADMIN_CODE`를 입력합니다.
3. Secret에는 **가족 코드와 다른** 12~64자 영문·숫자·기호 조합을 저장합니다. 16자 이상 무작위 문자열을 권장합니다. 값을 채팅이나 공개 저장소에 입력하지 않습니다.
4. GitHub Actions → `Publish Administrator Access Policy` → `Run workflow`로 실행해 초록색 성공 표시가 나오는지 확인합니다.
5. `data/admin_policy.json`의 `state`가 `ok`가 되면 v1.2의 `관리자 전환` 버튼에서 새 관리자 코드를 사용합니다.

관리자 비밀번호는 비공개 GitHub Actions Secret에서 관리합니다. 공개 저장소에는 별도 솔트와 PBKDF2-HMAC-SHA256 450,000회 도출한 검증값만 저장하며 평문은 기록하지 않습니다.
**기술적 한계:** 공개된 검증값은 오프라인 비밀번호 추측 공격을 완전히 막지 못합니다. 관리자 비밀번호는 길고 무작위여야 합니다. 전문적인 서버 측 인증이나 도난 기기별 철회 시스템은 아닙니다.

### 사용 방식

- 가족 모드 자동 로그인은 v1.1과 동일합니다.
- 관리자 전환은 온라인에서 최신 관리자 검증 정책을 읽고 관리자 비밀번호를 확인합니다. 인터넷이 없거나 아직 관리자 비밀번호를 설정하지 않았다면 안전을 위해 관리자 화면을 열 수 없습니다.
- **이전 버전에서 관리자 모드였다는 휴대폰 저장 기록은 더 이상 인정하지 않습니다.** 앱 실행은 가족 모드로 시작하며, 관리자에 들어갈 때마다 별도 관리자 비밀번호를 입력해야 합니다.
- 관리자 모드에서는 `보안 관리` 탭에서 가족 코드와 관리자 코드를 각각 변경할 수 있도록 비공개 GitHub 설정 및 수동 적용 작업으로 연결합니다. GitHub Secret의 원문을 앱으로 가져오거나 앱에 저장하지 않습니다.
- 관리자 코드 변경 시 이미 열려 있던 관리자 모드는 다음 앱 복귀·온라인 확인 때 가족 모드로 돌아갑니다.
- 가족 코드 변경은 기존 `FIRSTHYUNDAI_ACCESS_CODE`와 `Publish Family Access Code Policy`를 그대로 사용합니다.
- 고객 개인 메모는 기존처럼 기기별 로컬 저장이며 가족끼리 자동으로 공유되지 않습니다.

## v1.2 — 관리자 독립 인증 도입

앱 가족용 자동 로그인은 기존 방식과 동일합니다. `관리자 전환`은 가족 코드가 아닌 **별도 관리자 전용 비밀번호**로 인증합니다. 예전 v1.1의 저장된 관리자 모드는 더 이상 자동으로 인정되지 않습니다.

**관리자용 코드를 반드시 한 번 등록해야 관리자 메뉴가 열립니다.** 이 설정을 하지 않아도 부모님 가족 모드와 공개 실거래가/뉴스 조회는 계속 작동합니다.

1. GitHub 저장소 `Settings → Secrets and variables → Actions`에서 `New repository secret`을 클릭합니다.
2. **Name**은 정확히 `FIRSTHYUNDAI_ADMIN_CODE`로 입력하고, **Secret**에는 가족용 `FIRSTHYUNDAI_ACCESS_CODE`와 *다른* 영문·숫자·기호 **12~64자** 관리자 전용 비밀번호를 입력합니다. 16자 이상 무작위 문자를 권장합니다. 비밀번호를 채팅이나 공개 파일에 붙여 넣으면 안 됩니다.
3. GitHub `Actions → Publish Administrator Access Policy → Run workflow`를 실행합니다.
4. 성공하면 `data/admin_policy.json`의 `state`가 `ok`로 바뀌며 관리자가 앱의 `관리자 전환`에서 **새 관리자 전용 코드**를 입력할 수 있습니다.
5. 나중에 관리자 코드를 변경하려면 Secret을 다시 저장하고 **같은 워크플로를 재실행**합니다. 가족용 자동 로그인은 유지됩니다.

관리자 코드는 앱 안에 원문으로 저장하지 않습니다. 공개 GitHub에는 PBKDF2 검증값만 올라갑니다. 이 구조는 간편한 가족용 접근 분리이며 강력한 온라인 계정/기기별 접근 제어는 아닙니다.
관리자 확인은 온라인 연결이 필요하며, 앱을 종료하면 관리자 권한이 종료됩니다. 인증 5회 실패 시 1분간 잠금. 관리자 정책이 갱신되거나 온라인 확인이 실패하면 활성 관리자 화면은 다음 확인 시 가족 모드로 돌아갑니다.

**주의:** v1.1 이하로 다운그레이드하면 이전 보안 방식이 남아 있을 수 있습니다. 이전 디버그 APK를 배포/사용하지 않고 v1.2 이상 버전만 사용하세요.

## v1.1 — 최초 한 번 인증 후 자동 로그인과 원격 코드 변경

처음 설치한 기기에서 가족 보안코드를 한 번 인증한 뒤에는, 같은 코드를 사용하는 동안 다음 실행부터 자동 로그인합니다.
앱 시작 또는 오랫동안 사용하지 않다가 다시 화면으로 돌아올 때 GitHub의 공개 인증 정책(data/access_policy.json)을 HTTPS로 확인합니다. 코드가 달라졌으면 이전 인증을 무효화하고 새 코드를 요청합니다.
인터넷이 안 되면 최근 온라인 인증 정책을 확인한 시각으로부터 최대 24시간까지만 기존 캐시로 사용할 수 있습니다. 정책 확인 없이 영구적으로 이용하거나 모든 기기를 즉시 차단할 수는 없습니다.

### 관리자 모드 → 보안 관리

1. 'GitHub 보안코드 설정 열기' 버튼을 누르고 GitHub에 로그인합니다.
2. 저장소의 비공개 Actions Secret FIRSTHYUNDAI_ACCESS_CODE를 새 코드로 변경합니다. 코드 자체를 앱, 채팅, 공개 JSON에 쓰지 않습니다.
3. '새 보안코드 적용하기' 버튼을 눌러 Publish Family Access Code Policy 워크플로에서 Run workflow를 실행합니다.
4. 성공 후 부모님 기기에서 최신 정책을 확인하면 새 보안코드를 입력하게 됩니다. 이 과정은 v1.1 이상 앱에서만 작동합니다.

정확하게는 앱 내에서 직접 새 비밀번호를 입력받는 방식이 아니라, 관리자 탭이 GitHub 비공개 Secret 편집 화면과 변경 적용 화면으로 안내하는 구조입니다. GitHub 계정 인증 없이 공개 앱에 쓰기 권한을 주지 않기 위한 선택입니다.

공개 저장소에는 PBKDF2 검증값과 솔트만 기록되며 평문 비밀번호는 없습니다. 공개된 검증값은 오프라인 암호 추측 공격의 대상이 될 수 있으므로 영문·숫자·기호를 섞은 12자 이상 길고 무작위한 보안코드를 사용하세요.
가족 코드와 관리자 전환 코드는 아직 동일합니다. 별도 관리자 코드, 특정 휴대폰의 원격 차단은 다음 보안 단계로 남겨둡니다.
v1.0 이하 앱은 변경된 암호를 자동으로 받지 못합니다. 가족 휴대폰을 먼저 모두 v1.1 이상으로 업데이트하고 코드 변경을 이용하세요.
디버그 APK는 빌드마다 서명이 달라 업데이트 설치에 실패할 수 있으므로, 로컬 메모를 백업한 뒤 이전 앱을 삭제하고 새 APK를 설치하는 방법을 사용합니다.

## 새소식 — 신규 공개 확인일 기준 (v0.7)

- **새소식** 탭은 계약 체결 날짜가 아니라, 이전 국토교통부 API 조회에 없던 거래가 이번 조회에 처음 나타난 **신규 공개 확인일(한국시간)** 기준으로 매매·전세·월세를 날짜별로 보여줍니다.

- 저장 구조는 공공 데이터 `data/trades.json`과 별도로 `data/new_trades.json`을 관리하며, 최근 31일간 신규 확인 내역을 보관합니다. 이전 수집과 거래 조건을 비교하며, **정정 내용에 따라 기존 거래가 새 거래로 탐지될 가능성**은 남습니다.
- 현재는 매일 1회 수집을 기본으로 하며 GitHub Actions 예약 실행이 지연될 수 있습니다. **실시간 통지나 정확한 공식 게시일 추적이 아닙니다.**

## 가족 전용 보안코드 (v0.6)

**목적:** 퍼스트현대 APK를 설치한 사람이 가족 보안코드를 모르면 첫 실행 화면을 통과하지 못하도록 하는 간편 잠금입니다. 안드로이드의 **설치 자체**를 차단할 수는 없고, 기기별 원격 승인·차단도 지원하지 않습니다. 공개 GitHub 저장소의 소스와 공개 실거래가/뉴스는 여전히 누구나 볼 수 있습니다.

**보안코드 만들기 (코드를 채팅·공개 저장소에 쓰지 마세요)**

1. GitHub 저장소의 `Settings → Secrets and variables → Actions → New repository secret`에 들어갑니다.
2. **Name**: `FIRSTHYUNDAI_ACCESS_CODE`를 정확히 입력합니다.
3. **Secret**: 사용자님과 부모님만 아는 영문/숫자/기호 8~64자 조합을 입력합니다. 12자 이상을 권장합니다. 한글은 현재 지원하지 않습니다.
4. **Add secret** 클릭. 기존 국토교통부용 `DATA_GO_KR_SERVICE_KEY`는 **그대로 둡니다**. 두 비밀정보는 용도가 다릅니다.
5. 저장소 `Actions → Build Android APK → Run workflow`를 클릭합니다.
6. 성공 후 해당 빌드의 `Artifacts → FirstHyundai-Free-Auto-APK`에서 ZIP을 내려받아 압축을 풀면 `app-debug.apk`가 있습니다.
7. 갤럭시에 설치한 후 앱 아이콘을 열어 **가족 보안코드**를 입력하면 앱이 열립니다. 부모님도 같은 코드를 입력합니다.

실패 안내에 `FIRSTHYUNDAI_ACCESS_CODE GitHub Secret`이 나오면 코드가 아직 설정되지 않았거나 입력 조건에 맞지 않은 것입니다. 앱 소스 변경으로 인증코드가 GitHub에 유출되지 않게, 빌드시 GitHub Secret을 읽어 검증용 해시만 APK에 넣습니다. 다섯 번 틀리면 1분간 재시도가 제한됩니다.

> 보안 한계: 앱을 역분석하거나 공개 소스를 변경하는 사람까지 막을 수 없습니다. 강한 불법 복제 방지, 계정별 사용승인, 분실 휴대폰 접근 철회는 비공개 앱 소스와 인증 서버가 필요합니다. 0원·서버 없는 현재 설계에서는 **가족용 간편 잠금**까지만 제공합니다.
>
> 예전 v0.5 디버그 APK와 새 v0.6 APK는 빌드별 서명키가 달라 업데이트 설치가 안 될 수 있습니다. 이 경우 기존 앱의 **내 자료를 백업한 다음** 기존 앱을 삭제하고 새 APK를 설치하세요.

## 시스템 구성

```
        data.go.kr 국토부 API      구글 뉴스 RSS
                  \                 /
               GitHub Actions 자동 실행
                    | 공개 데이터만
           공개 GitHub 저장소 data/*.json
                    | HTTPS JSON 조회
              가족 휴대폰 APK 3대
                    |
              각자의 로컬 메모
```

**비용:** GitHub 공개 저장소 + 기본 Actions 호스티드 러너 무료 정책 범위에서 $0, 공공데이터 API 무료, RSS 무료, NLP Python 표준라이브러리 무료. 개인 인터넷 요금 제외. GitHub 서비스 정책·제한은 바뀔 수 있습니다. **생성형 AI API를 사용하지 않으며 비용 청구도 연결하지 않습니다.**

**보안:** 공개 저장소의 `data/news.json`, `data/trades.json`은 인터넷상 누구나 읽을 수 있습니다. 법적으로 공개된 자료·기사 링크만 저장하며 고객 이름, 연락처, 계약서, 개인 매물, 개인 노트, API 키를 올리면 안 됩니다. 소스코드도 공개됩니다. 가족 메모 자동 동기화는 지원하지 않습니다.

## 1단계 — GitHub 계정 및 공개 저장소 만들기

1. https://github.com/signup 에서 무료 계정을 만듭니다. 이미 계정이 있으면 로그인합니다.
2. https://github.com/new 로 이동합니다.
3. `Repository name`에 **firsthyundai-app** 입력.
4. `Visibility`는 반드시 **Public** 선택. (이번 무료 구조에서 인터넷으로 읽을 자료 JSON을 공개하기 위함. **Private로 만들면 이 설계대로 휴대폰에서 로그인 없이 읽을 수 없습니다**.)
5. README 파일 자동 생성은 체크하지 않습니다. `Create repository` 버튼 클릭.
6. 이 ZIP을 PC에 저장 후 압축을 풉니다. **압축을 푼 폴더 안의 내용물 전부**(숨김 `.github` 포함)를 저장소의 `Add file → Upload files` 영역에 올리고 `Commit changes`를 누릅니다. ZIP만 통째로 올리면 실행되지 않습니다.
7. GitHub 저장소 첫 화면에서 `app`, `data`, `scripts`, `.github` 폴더가 최상위에 있는지 확인합니다.

## 2단계 — 공공데이터 무료 키 발급 (아파트 매매·전월세 각각 활용신청)

1. https://www.data.go.kr/ 에서 무료 회원가입·로그인합니다.
2. [국토교통부 아파트 매매 실거래가 자료](https://www.data.go.kr/data/15126469/openapi.do) 페이지에서 `활용신청`을 누릅니다.
3. [국토교통부 아파트 전월세 실거래가 자료](https://www.data.go.kr/data/15126474/openapi.do)에서도 `활용신청`을 누릅니다.
4. 활용 목적 예시: `가족 공인중개사 사무실에서 송도동 아파트 실거래 공개자료를 조회하기 위한 내부 앱 연구 및 활용`.
5. 승인 후 마이페이지의 **일반 인증키(Decoding)** 를 복사합니다. 이용자에게 비공개입니다.
6. GitHub 저장소에서 `Settings → Secrets and variables → Actions → New repository secret`을 클릭합니다.
7. `Name`: `DATA_GO_KR_SERVICE_KEY` (정확히 대문자와 밑줄 포함).
8. `Secret`: 발급받은 **일반 인증키** 를 붙여넣고 `Add secret` 버튼을 누릅니다.
9. 절대로 Secret 값을 GitHub 파일에 붙여넣거나, 채팅·스크린샷에 노출하지 마세요.

> 두 서비스의 권한이 모두 활성화된 상태에서 요청해야 합니다. API 무료 할당량과 접근 가능한 응답 필드 등은 공공데이터포털 이용조건에 따릅니다.

## 3단계 — GitHub 자동 저장 권한 설정

1. GitHub 저장소의 `Settings` 클릭.
2. 왼쪽 `Actions` → `General`.
3. 화면 아래 `Workflow permissions`에서 **Read and write permissions** 선택.
4. `Save` 클릭. (저장소 정책에서 해당 항목이 제한되면 소유자 계정 권한을 확인하세요.)

## 4단계 — 먼저 뉴스만 실행해 보기 (API 키가 없어도 가능)

1. 저장소 상단 **Actions** 클릭.
2. 처음 실행 화면이면 `I understand my workflows, go ahead and enable them` 등 활성화 버튼 클릭.
3. 왼쪽 `Update Public Data (FREE)` 선택.
4. 오른쪽 `Run workflow` 버튼 클릭.
5. 실행 옵션 `news`를 선택하고 다시 초록색 `Run workflow` 클릭.
6. 실행 목록에 새 작업이 나타납니다. 완료 후 초록색 체크 표시가 나오면 성공입니다.
7. 저장소에서 `data/news.json`을 열어 `state`가 `ok` 또는 `partial`로 바뀌었는지 확인합니다. 뉴스가 하나도 없을 때도 실제 빈 결과를 보여줄 수 있으며, 가짜 뉴스를 넣지 않습니다.

## 5단계 — 실거래가 실행해 보기 (키 발급 후)

1. 같은 `Actions → Update Public Data (FREE) → Run workflow`.
2. 옵션을 `trades`로 설정한 후 실행.
3. 성공하면 `data/trades.json` 파일의 `state`, `checked_at`, `count`가 업데이트됩니다. `records` 안에 실제 계약이 담기며 조회 오류가 있으면 `partial` 상태가 됩니다.
4. **연수구 전체에서 송도동만 추출**, 매매·전월세가 구분됩니다. 날짜는 **계약일** 기준이고, 취소 거래는 `해제`로 표시됩니다.
5. 실패했다면 Actions의 빨간 X → 작업 → 오류 단계를 클릭해 확인하세요. 키·승인·사용량·서비스 장애로 실패할 수 있습니다. 키 내용은 외부에 공유하지 마세요.

> `Run workflow → all`을 선택하면 뉴스와 실거래가를 한 번에 실행합니다. 첫 사용에서 키가 준비되지 않았다면 `news`부터 실행하세요.

## 6단계 — 자동 실행

- 뉴스: `17 */3 * * *` (UTC 기준 3시간마다 17분).
- 실거래가: `41 19 * * *` (UTC, 한국시간 매일 새벽 04:41).
- 예약 실행은 GitHub 서버 사정으로 지연되거나 누락될 수 있고, 장기 비활성 저장소의 workflow가 비활성화될 수 있습니다. **3시간마다 무조건 발행이 보장되지는 않습니다.**
- 자동으로 실행되면 JSON 파일이 **공개 저장소에 커밋**되며 APK에서 읽습니다.
- 60일 이상 비활성 저장소의 예약 작업 자동 중지 여부 등은 최신 GitHub Actions 정책을 확인하세요.

## 7단계 — APK 만들기 (PC에 Android Studio 불필요)

1. GitHub 저장소 상단 **Actions** 클릭.
2. 왼쪽 **Build Android APK** 클릭.
3. `Run workflow → Run workflow` 클릭.
4. 초록색 성공 체크가 표시되면 실행 결과를 누릅니다.
5. 아래쪽 `Artifacts`에서 **FirstHyundai-Free-Auto-APK** 다운로드.
6. 내려받은 ZIP의 압축을 풀면 `app-debug.apk` 파일이 나옵니다.
7. 본인 휴대폰으로 옮겨 갤럭시의 **내 파일** 앱에서 열어 설치합니다. 개인 개발 테스트 APK라 Google Play 배포용 서명 앱이 아닙니다.
8. 설치가 차단되면 갤럭시에서 경고 내용을 확인하고 신뢰할 수 있는 직접 빌드한 파일인지 확인하세요.

> 코드만 제공되는 현재 버전은 **이 환경에서 Android SDK로 빌드하거나 실기기에서 검증하지 못했습니다**. GitHub 빌드에서 오류가 발생하면 오류 로그를 확인해 수정해야 합니다.

## 8단계 — APK에서 데이터 연결

1. 퍼스트현대 앱 실행 → `설정` 탭.
2. `공개 GitHub 저장소 주소` 칸에 `GitHub아이디/firsthyundai-app` 입력. 예: GitHub 계정이 `abc123`이면 `abc123/firsthyundai-app`.
3. `저장하고 불러오기` 버튼 클릭.
4. `전체 브리핑`에서 실거래 건수와 뉴스 제목 묶음이 표시되면 연동 성공.
5. `실거래가` 탭에서 단지명을 검색하고 매매/전세/월세를 선택할 수 있습니다.
6. `뉴스 브리핑` 탭에서 개발·교통 등 분야별 언론 보도 묶음과 링크를 확인할 수 있습니다.
7. 부모님 휴대폰에도 같은 APK를 설치하고 **같은 GitHub아이디/저장소**를 입력하면 **공개 자동 자료**를 함께 봅니다. **각자의 ‘내 자료’ 메모는 공유되지 않습니다.**

## 출처와 실무상 해석의 한계

- 매매 공식 자료: https://www.data.go.kr/data/15126469/openapi.do
- 전월세 공식 자료: https://www.data.go.kr/data/15126474/openapi.do
- 정부 API에 신고·공개되지 않은 거래는 이 앱에도 나타나지 않습니다. 신고 지연, 계약 취소, 정정이 있을 수 있습니다.
- **오피스텔/분양권/상가**는 현재 구현되지 않았습니다. 각 부동산 유형별 공공 API 연동이 별도로 필요합니다.
- 언론 뉴스: Google 뉴스 RSS 제목·링크·매체·발행일만 사용. 원문 기사 본문을 복제하지 않습니다. 저작권, 인용, RSS 이용조건을 확인하여 사용하세요.
- `브리핑`은 TF-IDF 기반 기사 제목 유사도 묶음이며 **생성형 AI 모델의 종합분석이 아닙니다**. 여러 매체에서 보도했다는 사실만으로 정부가 확정한 계획은 아닙니다.
- 세금/대출/법령 시행일은 이 버전에서 검증하지 않습니다. 고객 안내 전에 국토교통부/국세청/금융위 등의 **공식 원문과 적용일**을 대조하세요.

## 개발자용 간단 테스트

```sh
python -m unittest discover -s tests -v

DATA_GO_KR_SERVICE_KEY='발급받은키' python scripts/collect_trades.py --months 12
```

## 오류 해결

- 앱에 `404`: GitHub 저장소가 Public인지, `data/trades.json` / `data/news.json` 파일이 `main` 브랜치에 있는지 확인.
- JSON 상태 `not_started`: Actions에서 데이터를 실제로 한 번 수집해야 합니다.
- GitHub `403` 또는 권한 오류: `Settings → Actions → General → Workflow permissions`에서 쓰기 권한 확인.
- 수집 작업 실패: `DATA_GO_KR_SERVICE_KEY` Secret 이름·API 2종 활용신청·승인 여부 확인.
- 뉴스를 볼 수 없거나 0건: RSS 서비스 연결 상태, 필터 기준(최근 7일), GitHub Actions 로그 확인.
- APK 빌드 실패: GitHub Actions `Build Android APK` 실행의 빨간 실패 단계 로그 확인.
- 앱에서 자료가 오래됨: 공개 JSON `checked_at`을 확인. 예약 실행이 누락되었을 수 있으니 Actions에서 수동 실행.
