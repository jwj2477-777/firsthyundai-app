조사 기준: 2026-10-22 · 저장된 `data/complexes.json` 및 앱의 국토교통부 실거래 원본 처리 규칙. 아래 집계는 **앱에 공개·등록된 자료**에 대한 전수조사이며, 모든 분양 타입이 확인됐다는 의미는 아닙니다.

- 등록 95개 항목 중 합산 관리용 2개를 제외한 **93개 개별 단지** 전수조사.
- 공급·전용이 출처로 매칭된 주택형 대응표 **576개** 보존.
- 저장된 공식 실거래 전용면적 중, 검증된 공급·전용 대응표에 정확히 걸리지 않아 **화면에 새로 표시할 전용면적 185종 (중복 없는 단지별 집계)**.
- 그에 해당하는 단지는 **41곳**. 기존 화면에서는 모두 또는 일부가 표시되지 않았음.
- 앱은 위 면적과 새로 갱신되는 실거래 기록에서 관측된 면적을 합쳐 표시. 공급면적·평형을 알 수 없는 자료에는 공급면적을 **만들어 넣지 않음**.
- 검증된 타입의 평형은 공급㎡ 기준, 확인되지 않은 추가 면적은 **전용㎡만**. 이름이 비슷한 20블럭/25블럭 등은 단지별 별도 집계.
- 전용 타입의 신규 실거래가 이후 추가되면 자동 반영되며, 국토교통부에서 계약 기록이 없는 법정 타입까지 존재를 주장하지는 않음.

## 계약문자 연동 규칙

- 단지 상세의 **이 단지로 계약문자 작성** 버튼: 해당 단지의 실제 이름·도로명 주소를 상단 큰 메모 입력칸과 수기 항목에 채워줌.
- **이 면적으로 계약 작성** 버튼: 그 면적을 추가로 입력. 검증된 공급·전용 대응표가 있는 타입만 공급타입·공급㎡도 함께 기재.
- 계약 메모 자동 분석을 실행해도 단지명·주소·면적이 보존됨.
- 새 계약 작성 전 기존 고객의 메모/계좌가 있다면 교체 여부를 확인한 후 초기화하며, 자동 송금액·동호수·거래금액은 **절대 추정하지 않음**.
- 계약 정보는 기기 안에서만 다루며 외부 AI/서버에 송신하지 않음.

참고 데이터: `data/complexes.json`의 공급·전용 대조 출처 및 `data/trades.json`의 국토교통부 실거래가 공개 API 전용면적. 공급면적 대응을 수동 추가하려면 동일 단지의 공급㎡와 전용㎡가 한 쌍으로 확인되는 출처가 필요합니다.
