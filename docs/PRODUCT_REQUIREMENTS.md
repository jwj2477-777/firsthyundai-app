## 2026-10-28 · v2.1.34 · 6개 주메뉴 스크롤 반응형 압축
- 유저 요청: 상단 맨 위에서는 기존 6개 메인 아이콘/버튼과 3×2 배열을 그대로 유지하고, 아래 내용을 보려고 스크롤하면 **각 버튼의 높이·아이콘·글자·간격**이 170 CSS 픽셀 범위에서 부드럽고 연속적으로 줄어든다. 페이지 최상단으로 돌아오면 완전 복원.
- 새 `app/src/main/assets/nav-collapse.js`는 수동 DOM 재생성, 메뉴 위치 변경이나 다른 애니메이션을 넣지 않는다. passive scroll + requestAnimationFrame 하나와 cubic smoothstep을 적용한다. 앱 사용자의 모션 줄이기 설정에서는 순간 전환한다.
- `nav-collapse.css`가 기존의 6개 메뉴 순서/색상/선택 효과를 보존하고, 압축형은 약 58px 높이의 3×2 버튼으로 유지하여 상단 고정(nav sticky)으로 하단 콘텐츠에 바로 접근한다. 모든 메뉴는 최소 48px 높이를 유지하고, 기본 큰 화면은 기존 80~95px 검증 범위다. 관리자 추가 메뉴도 유지.
- 메뉴 버튼 재생성 시 `renderMainNavigation`은 상태를 새로 초기화하지 않고 ScrollController만 갱신한다. 색상 이동 동작 `selection-flow.js`와 터치효과·리듀스드 모션 설정을 보존한다. 계약문자, 실거래, 날씨, 캘린더 및 v2.1.33의 설치 권한 최소화도 보존.
- 기존 `test_six_nav_header_geometry_browser.js` / `test_compact_nav_dock_browser.js`와 새로운 `test_nav_scroll_collapse_browser.js`를 사용해 실제 Chromium 320/360/393/430px에서 메뉴 6개, 원래 배치, 일부 스크롤 시 중간 높이, 완전 압축, 접근성 48px 및 정상 복귀를 검증한다.
- 디바이스에서 스크롤과 각종 오버레이(상세 날씨, 아파트 상세 화면) 실제 사용성은 추가 수동 검토 대상으로 남긴다.

## 2026-10-27 · v2.1.31 · 관심 단지 실거래 알림함 상세 재열기
- 알림함에서 '관심 단지 새 실거래 N건'을 누르면 전체 새 거래 화면으로 잘못 이동하던 경로를 수정. 기록에 해당하는 관심 14개 단지 전용 실거래 팝업을 다시 열고 각 단지·거래유형·금액·계약일·면적·층 등 실제 제공 필드를 보여준다. 팝업은 건수가 많아도 일부 3건만 자르지 않고 해당 알림의 거래 전체를 표시한다.
- 향후 Android 로컬 실거래 알림 발송 성공 시 그 알림에 속한 공개 거래의 **최소 필드만** Native 비공개 알림 기록(90일/최대80건)에 함께 저장해 앱 재시작 후에도 동일 내역을 복원한다. 공유메모·고객·연락처·계좌 자료는 이 기록에 저장하지 않는다. 신규 알림 감지 기준·첫 스냅샷 기준선·팝업 켜기/끄기·가족 인증·비공개 저장 정책은 보존한다.
- 과거 알림에는 거래 스냅샷이 없으므로 원래 기록된 **단지별 건수 요약**을 팝업으로 복원한다. 현재 공개자료에서 알림 당일의 단지별 건수가 모두 정확히 일치할 때만 현재 자료로 재조회한 거래를 구분해 보여준다. 일치하지 않으면 실제 거래를 임의 추측하거나 다른 거래로 바꾸지 않는다.
- 상세의 '해당 거래 보기'는 해당 거래 ID에 집중하며 기존 '관심 14개만' 필터를 유지한다. 과거 기록에 개별 ID가 없다면 전체 거래가 아니라 관심 14개 새 거래만 보여준다. 데이터 미수신 시 관련 이동 버튼은 일시 비활성화한다.
- 회귀 테스트: `test_notification_inbox_browser.js`(현행·레거시 기록 재열기, 전체 새 거래 오이동 방지), `test_favorite_trade_alerts.js`(별도 스냅샷·다건·레거시 요약), `test_android_trade_notifications.js`(Native 알림 스냅샷 기록). 실제 APK 배포 여부는 CI와 Release 검증 이후에만 확정한다.


## 2026-10-27 · v2.1.30 · 시간별 예보가 비어 있던 실제 원인과 수정
- 실제 화면: 퍼스트현대 상세 날씨에서 15.4°C 초단기실황은 정상인데 시간별 그래프와 최고/최저가 모두 미표시, 길게 빈 카드가 나타남.
- 확인된 근본 원인: `SharedSettingsClient.call()` 공통 response size cap `>5000` bytes. GitHub `data/songdo_weather.json`의 검증된 송도 단기예보는 당시 80시간, minified JSON 약 6.5KB로 제한을 초과함. Android는 내부 예외를 그대로 정상 fetch 실패로 처리하여 앱은 예보를 받지 못함. 초단기실황은 매우 작아 정상 수신.
- 수정: `/weather-briefing` 경로에만 64KiB(65536) 상한, 그 외 /settings 등 기존 5KB 유지. Worker의 기존 스냅샷, 키, 접근 정책 유지. `scripts/test_weather_native_transport.js`에서 실제 크기의 80시간 예보 JSON이 5KB 초과함을 재현하고 12시간 검증과 선택 상한 테스트 추가.
- 그래프가 비었을 때 238px의 고정된 빈 박스를 없애고, 작은 안내 줄만 남겨 데이터 없음을 정직하게 표현. 기존 날짜, 현재 날씨, 일정, 지도함 기능 및 기존 화면은 보존.
- 추가 API 조사: 먼저 기존 승인된 `기상청_단기예보 조회서비스`(https://www.data.go.kr/data/15084084/openapi.do)의 `TMN`/`TMX`, `REH`, `WSD`와 초단기예보를 재사용. 별도 신규 후보로 기상청 기상특보 조회서비스(https://www.data.go.kr/data/15000415/openapi.do), 한국환경공단 에어코리아 대기오염정보(https://www.data.go.kr/data/15073861/openapi.do), 한국천문연구원 출몰시각 정보(https://www.data.go.kr/data/15012688/openapi.do). 해당 별도 API 연결 및 승인 상태는 검증 전이며, 이번 버전에 데이터가 있는 것처럼 표시하지 않는다.
- 배포확인은 앱 패키지 2.1.30/build181, CI 테스트와 APK signing consistency 확인, GitHub Release 및 `data/app_latest.json` 링크 검증까지 별개 완료 조건으로 유지.
