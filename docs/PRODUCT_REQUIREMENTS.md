## P1 / 실거래 — 가장 자주 회귀한 영역
- [x] 공개 API: 인천 연수구 **송도동** 아파트의 매매/전세/월세. 최근 12개월 계약월 재수집; 지연 신고·정정·해제 반영. 정렬은 실제 **계약일** 기준. 필터 및 관심단지 보기.
- [x] 매매: 거래 유형 **중개거래 / 직거래**를 데이터가 제공할 때 표시. 중개거래에만 **중개사 소재지** 표시. 직거래에 엉뚱한 중개사무소 정보 붙이지 않음.
- [x] 전월세: 정부의 `contract_type_raw` 기준으로 **신규계약 / 갱신계약 / 계약구분 미기재**를 구분. 갱신요구권 사용 데이터만 보고 갱신계약이라 단정 금지.
- [x] 갱신계약에만, 큰 금액 표시와 계약일 아래 **보조정보 네 가지** 표시: ① 계약갱신요구권 사용 여부 (`renewal_raw`) ② 계약기간 (`contract_term_raw`) ③ 종전 보증금 (`previous_deposit_raw`) ④ 종전 월세 (`previous_monthly_raw`). 값이 원본에 없다면 각각 **미기재**, 실제 **0원은 0원** 유지. 신규·매매에는 이 영역 없음.
- [x] 거래카드에서 **'출처: 국토교통부'**, **'조회 계약연월'** 등 불필요한 반복 제거; 대신 **실제 계약일**, 전용면적, 층, 거래 종류/금액 유지. 별도 필요한 법적 안내는 유지.
- [x] 취소 거래를 일반 거래와 구분: 빨간 해제 상태, 원본에서 확인되는 해제일·사유일.
- [x] **전체 최신순, 관심 14개 단지, 새소식** 세 렌더링 경로를 일치시킬 것. 주된 회귀 테스트: `scripts/test_trade_contract_regression.js`.
- [x] **새로 확인된 거래**: 정부 신고일/공개일 대신 프로그램의 첫 관측 `first_seen_date`임을 적시. 같은 계약 정정·취소 재수집을 신규로 오판하지 않도록 백엔드 아이덴티티 확인.
- [x] 거래 종류 매매/전세/월세는 텍스트와 구분 가능한 색으로. 검색·면적 필터, 단지 별도 상세 화면 및 복귀 시 상태 유지.
- [ ] 특수 유형(오피스텔·분양권 등)은 승인된 별도 공식 API 자료만 독립 영역에 넣을 것. 아파트 거래와 섞지 않기.

## P1 / 계약 문자 작성 및 실무 위험
- [x] 자연어 자유 메모 **하나**에서 거래종류·아파트·주소·동호·금액·계약금 일부/송금·중도금·잔금·예금주·은행·계좌·특약 등을 인식, 수동 확인 및 교정 후 문자를 복사/공유.
- [x] 송금액·예금주 이름·은행·계좌번호 **네 요소는 임의 순서**. `오늘 500`, `금일 천만원` 등 한국어 금액, 띄어 쓴 계좌번호, 동/호수, 잔금일, 계약 총액 혼동을 줄이되 완전 무오류 주장 금지.
- [x] 중도금 없는 거래는 항목 생략; 계약금 10%/잔금 등 계산은 불확실할 때 확인. 계약금 일부를 전체 계약금과 혼동하지 않음. '선송금액' 불필요한 중복 열은 기본 가격표에서 제거하고 문맥상 자연스럽게 서술.
- [x] 수동 특약은 원본 보존, 불확실한 문구/맞춤법은 의미 훼손 없이 정리·원문 비교/복원.
- [x] 필수 기본 특약: **'기타 상세한 특약사항은 본계약서 작성 시 협의하여 기재한다.'**; 사용자가 동등한 문장을 이미 넣었으면 중복 금지.
- [x] 이미 명시적 합의한 부분계약금/계약 성립·해제·배액상환·중개보수 문구는 합의 내용 반영; **합의 여부 확인**. 민법 제565조 "당사자 간에 다른 약정이 없는 한" 조항과 사용자 합의 범위를 지키고, 미합의 고객에게 획일적으로 강요하거나 법적 효력을 단정하지 않기.
- [x] 실제 고객 실명/계좌/송금액/전화번호/계약서는 개인 정보. 공개 저장소의 커밋·스크린샷·테스트 데이터에 넣지 않음. 기기 내 분석, 외부 AI 업로드 금지. 고위험 안내는 최종 확인 필수.
- [x] 최종 승인한 계약문자 원문을 외부 업로드 없이 Canvas PNG로 시각화, 긴 특약은 페이지 분할, 앱 공유 시 캐시 파일 FileProvider를 통해 전송. 내용 수정 후 재승인 필수, 이미지 미리보기 확인 필수. 원문 누락·임의 합의 생성 금지.
